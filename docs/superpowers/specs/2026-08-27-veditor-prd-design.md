## 1. 产品定位与目标

### 1.1 概述

VEditor 是面向专业/半专业创作者的开源桌面视频编辑器,以原生 Rust + FFmpeg 内核实现远超剪映的导入速度、预览流畅度与导出性能,交互对标剪映的易用性但面向专业工作流。

### 1.2 目标用户

| 用户群 | 场景 | 核心诉求 |
|---|---|---|
| 专业剪辑师 | 商业片、宣传片、口播视频 | 多轨、精确到帧的编辑、稳定不崩溃 |
| 半专业创作者 | B站/YouTube 中长视频 | 剪映级易用性 + 专业级深度功能 |
| 从剪映迁移来的用户 | 已有素材库和工作习惯 | 兼容剪映草稿导入(差异化亮点) |

### 1.3 对标剪映的差异化优势(成功标准)

性能指标(可量化验收):

| 指标 | 剪映参考值 | VEditor 目标 |
|---|---|---|
| 4K 素材导入到可编辑 | 30-60s+(需生成完整代理) | **<10s**(惰性代理,边播边生成) |
| 1080p 8轨时间轴预览 | 间歇掉帧 | **稳定 60fps**(GPU 合成) |
| 10分钟 1080p 导出 | ~8-15min | **<5min**(FFmpeg 直通 + 多 pass 并行) |
| 内存占用(1h 项目) | 4GB+ | **<1.5GB**(流式处理,零拷贝) |
| 启动到可编辑 | 3-5s | **<1.5s**(惰性加载) |

交互优势:

- 全键盘可操作(专业剪辑习惯:JKL、波纹删除等快捷键)
- 剪映式的"低门槛入口" + 专业模式的"深功能"共存
- 撤销栈无限级、秒级恢复

### 1.4 非目标(v1.0 明确不做)

多人协作/云同步、素材市场、移动端、录屏、直播。

## 3. 技术架构设计

### 3.1 总体架构

```
┌─────────────────────────────────────────────────────┐
│  UI 层 (React 18 + TS, WebView)                     │
│  Canvas 时间轴 │ 预览画布 │ 面板/弹窗 (Phosphor)     │
└──────────────┬──────────────────────────────────────┘
               │ Tauri invoke (命令) / emit (事件,双向)
┌──────────────▼──────────────────────────────────────┐
│  app crate: 命令层(参数校验/序列化) + 事件推送        │
├─────────────────────────────────────────────────────┤
│  core      │  render      │  export    │  ai         │
│  文档模型   │  Renderer    │  FFmpeg    │  whisper    │
│  命令栈     │  trait +     │  滤镜图    │  .cpp 任务  │
│  快照序列化 │  代理引擎     │  导出管线  │  队列       │
├─────────────────────────────────────────────────────┤
│  media: 导入探测/缩略图/波形/代理生成 (线程池)        │
└─────────────────────────────────────────────────────┘
```

### 3.2 Crate 职责与边界

| Crate | 职责 | 关键依赖 | 禁止 |
|---|---|---|---|
| `core` | 时间轴/轨道/片段/关键帧数据模型、Command 撤销栈、项目快照(serde 序列化) | serde 仅此 | 任何 IO、FFmpeg 调用 |
| `media` | ffprobe 元数据探测、缩略图/波形生成、惰性代理转码 | ffmpeg-sidecar(进程托管 FFmpeg) | 理解业务模型 |
| `render` | `Renderer` trait:`seek(t) -> Frame`、`play(range)`;MVP 实现 `ProxyRenderer` | media 产物 + 内存映射帧缓存 | — |
| `export` | 文档模型 -> FFmpeg 滤镜图/命令行编译器;导出队列、进度事件 | ffmpeg-sidecar | 阻塞 UI 线程 |
| `ai` | whisper.cpp 绑定(本地 ASR)、任务队列、字幕对齐输出 | whisper-rs | 联网 |
| `app` | Tauri commands(薄层)、AppState(RwLock 共享)、事件桥 | 以上全部 | 业务逻辑 |

依赖方向:`app -> {core, media, render, export, ai}`;`render/export/ai -> core`(只读消费文档模型)。

### 3.3 关键设计决策

#### Renderer trait(支撑"先代理后实时")

```rust
pub trait Renderer: Send {
    fn seek(&mut self, t: Time) -> Result<FrameHandle>;
    fn play(&mut self, range: TimeRange, speed: f32) -> Result<FrameStream>;
    fn invalidate(&mut self, changed: &TimelineDiff);  // 编辑后精准失效缓存
}
```

MVP `ProxyRenderer`:代理片段 + 拼接预渲染。v1.1 `RealtimeRenderer`(wgpu GPU 合成)实现同 trait,UI 零改动。

#### 编辑命令流(撤销/协作基础)

所有编辑 = `Command` 对象(正向 apply + 逆向 undo),经 `core::CommandStack` 入栈;每次命令后对文档做结构化快照(追加式,增量存储)。崩溃恢复 = 重放最近快照 + 命令日志。

#### 线程模型

- UI(WebView)+ Tauri 主线程:只做命令分发与事件推送,零重活
- `media` 线程池(rayon):探测/缩略图/代理生成,按素材优先级调度(时间轴可见片段优先)
- `export`/`ai`:独立任务队列,进度经 Tauri event 推送
- 帧缓存:内存映射文件 + LRU,内存上限可配(默认 1GB)

#### 前端架构

- 状态:Zustand + Tauri invoke 封装;文档真源在 Rust,前端持投影副本,编辑走命令、经事件回传确认(避免双源冲突)
- 时间轴:Canvas 2D 自绘 + 虚拟化(仅绘制可视区),交互用 pointer events,支持万级片段
- 预览:MVP 用 `<video>`/WebCodecs 播代理片段;实时引擎阶段升级 WebGL 合成
- 图标:Phosphor Icons(react 组件,与 egui_phosphor_icons 同源同风格)

### 3.4 数据流示例(拖入素材 -> 预览播放)

1. 拖入 -> `import_media` command -> `media` 探测元数据 + 立即返回占位(不等代理)-> 导入 <10s 达标
2. 代理任务入队(后台,按需);缩略图/波形流式生成,事件推送逐个刷新 UI
3. 播放 -> `Renderer.play()` -> 代理就绪片段直接播;未就绪段降级播原片低分辨率 seek(边播边补代理)
4. 编辑 -> Command -> 文档更新 -> `TimelineDiff` -> 缓存精准失效 -> 事件通知 UI 重绘

### 3.5 错误处理与测试策略

| 层 | 策略 |
|---|---|
| FFmpeg 进程 | 崩溃自动重启 + 任务重试(指数退避);stderr 解析为用户可读错误 |
| AI 推理 | 模型缺失 -> 引导下载;降级:禁用 AI 功能不阻塞主流程 |
| core | 单元测试覆盖命令栈/快照往返(序列化反序列化等价性) |
| export | 滤镜图生成器 golden-file 测试;端到端:小项目导出后 ffprobe 校验 |
| 前端 | Vitest 组件测试;时间轴交互 Playwright 冒烟 |
| 性能回归 | CI 基准(criterion):命令延迟 <5ms、快照 <50ms |

## 4. 性能工程要点

| 指标 | 工程手段 |
|---|---|
| 导入 <10s | 惰性代理:ffprobe 探测(<200ms)即返回可编辑状态,代理后台按需生成;缩略图/波形流式产出 |
| 预览 60fps | MVP:代理片段 + 预渲染拼接缓存;v1.1:wgpu GPU 合成 + 零拷贝纹理上传;帧缓存 LRU 内存映射 |
| 导出 <5min/10min | FFmpeg 流式直通(能不重编码就不重编码)、分段并行(按片段切分多进程合成再 concat)、x264 preset 自动权衡 |
| 内存 <1.5GB | 帧缓存上限可配 + mmap 淘汰到磁盘;文档快照增量追加;缩略图按需生成不全集驻留 |
| 启动 <1.5s | 惰性初始化 crate;首屏只加载 UI 骨架,媒体库后台刷新 |
| 命令延迟 <5ms | Command 仅操作内存文档,重活(失效缓存/重绘)异步化 |

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| WebView(Linux WebKitGTK)性能/兼容坑 | 高 | M0 即在目标环境做 Canvas/WebCodecs 能力验证;预览解码放 Rust 侧,WebView 只做纹理呈现 |
| 代理方案 seek 拖动不流畅 | 中 | 关键帧密集的低码率代理 + 拖动时降帧率预览(拖动 8fps、松手恢复) |
| whisper.cpp 大模型内存/速度 | 中 | 模型分档(tiny/base/small)供选择;推理独占线程池,不阻塞编辑 |
| 剪映草稿格式逆向(无官方文档) | 中 | 社区已知格式研究 + 容错解析(解析失败的原样跳过并提示),P1 定位允许不完美 |
| FFmpeg 滤镜图复杂拼接出错 | 中 | 滤镜图编译器 golden-file 测试 + 每次导出前 dry-run 校验 |
| 全功能+AI 范围过大延期 | 高 | 严格按里程碑门禁:每阶段性能验收不过不进下一阶段;P1/P2 可裁剪 |
| 单人 Linux 先行,缺真机验证 | 低 | M4 前建立 AppImage 自动构建 + 社区内测渠道 |
